1. Checked vs Unchecked Exceptions

1.0.1. Unchecked Exceptions

Also called runtime exceptions, result from programming errors (I.e. null pointer dereferencing or out-of-bounds array access).

  1. Examples
    • RuntimeException
    • Error
    • NullPointerException
    • ArithmeticException
    • and their subclasses

1.0.2. Checked Exceptions

Must be handled at compile time using try-catch blocks or declared with the throws keyword.

The compiler forces the programmer to check and deal with them in a try-catch block or declare it in the method header.

  1. Examples
    • IOException
    • SQLException

1.0.3. Errors

Critical issues that an application typically cannot recover from.

  • OutOfMemoryError
  • StackOverflowError

1.0.4. Summary

In most cases, unchecked exceptions reflect programming logic errors that are unrecoverable.

  1. Examples
    • A NullPointerException is thrown if you access an object through a reference variable before an object is assigned to it.
    • An IndexOutOfBoundsException is thrown if you access an element in an array outside the bounds of the array.

    These are logic errors that should be corrected in the program.

    Unchecked exceptions can occur anywhere in a program.

    To avoid cumbersome overuse of try-catch blocks, Java does not mandate that you write code to catch or declare unchecked exceptions.
